01
HASH / 内容指纹

SHA-256 为什么没有“解密”按钮？

摘要、加密、密码存储，先分清这三件事。

+

SHA-256 会把输入转换为固定长度的摘要。改动一个字符，通常就会得到完全不同的结果。你可以在上面的工具里，把“你好”改成“你好！”，观察变化。

哈希没有对应的解密操作。不过，对容易猜到的输入，别人仍可逐个尝试并比较摘要。因此，直接用一次 SHA-256 保存密码并不合适；密码存储需要专门的方案。

02
ENCODING / 字节与文本

Base64 看不懂，就代表安全吗？

把中文和 emoji 编码，再亲手还原回来。

+

Base64 是把字节表示成一组可打印字符的编码方式。它不需要密钥，知道编码规则就能解码，所以不能拿来保护秘密。

本页先把文本转为 UTF-8 字节，再做标准 Base64 编码。解码时也会检查结果是不是有效的 UTF-8 文本；图片或任意二进制数据的 Base64 不一定适合这个文本工具。

03
WEB / 一个小细节

URL 里的 % 和 + 是怎么回事？

路径、参数值和表单编码，规则有时不一样。

+

当你把一段文本放进 URL 的参数值时，空格、中文和一些符号需要编码。例如，空格可以变成 %20，加号可以变成 %2B。

本页使用 encodeURIComponent 与 decodeURIComponent，适合单独的参数值。它不会把解码输入中的 + 自动当成空格，也不会代你解析整条 URL。
